## Конфигурации

Три и четыре Worker проверены в Express на партии Морфи с эмулированными 8 логическими ядрами. Фактическая квота осталась 2 vCPU.

- 3 × 1, Instant 1.47 с, итог 4.12 с, пик PSS 553 МиБ.
- 4 × 1, Instant 1.74 с, итог 4.74 с, пик PSS 598 МиБ.

Для этого стенда выбран пул из двух однопоточных Worker. Конфигурации с одним Worker измерены отдельными прогонами с теми же лимитами на промежуточной сборке. По времени однопоточный прогон пересекался с браузерными тестами. Результаты описывают наблюдения на этом стенде.

Физические Redmi Note 12 и iPhone 17 были недоступны. В эмуляции Chromium и WebKit прошли офлайн-разбор с двумя Worker и проверка ширины страницы. Быстродействие, нагрев и системные ограничения памяти физических устройств остаются неизмеренными. Защита от падения производительности опирается на наблюдаемую скорость и ошибки Worker. Автоматический проход выполняется при открытом приложении.

Воспроизведение

`BENCH_WORKERS=2 BENCH_MODES=quick,standard node --import tsx scripts/benchmark.mjs http://localhost:4173 result.ndjson`

Для последних четырёх полуходов установите `BENCH_TAIL=4 BENCH_MODES=deep,professional`. Для одного многопоточного Worker используйте `BENCH_WORKERS=1 BENCH_THREADS=auto` при поддержке SharedArrayBuffer. На стенде для этого запуска браузеру сообщалось о четырёх логических ядрах. Скрипт сохраняет WDL, лучшие ходы, глубину, категории и объяснения по всем полуходам.
